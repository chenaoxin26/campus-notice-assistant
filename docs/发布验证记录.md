安装检查在现有 Windows 电脑的独立 Python 环境中进行，没有重装 Windows，也没有逐个测试所有 Python 版本。最低要求写为 Python 3.11，实际检查过的版本是 3.12 和 3.14.9。

## 12 项本机运行检查

1. 第一次启动没有群名单和任务，监听没有自动开启。
2. 只查看界面不会自动分析消息。
3. 可以手动导入虚构通知。
4. 可以调用本机模拟模型接口生成任务。
5. 没有明确时间地点时保持待确认。
6. 任务完成后，再次导入相同通知不会变回未完成。
7. 群名单可以添加，也可以清空。
8. 退出并重新启动程序，完成状态仍保留。
9. 模型连接失败时，仍能查看已有任务。
10. 模型连接失败时，仍能导出 Excel。
11. 表格中的完成状态和原文来源正确。
12. 程序正常退出，不影响其他模型服务。

这 12 项使用模拟模型，检查的是程序能否正确调用和处理结果，没有再次验证真实 Qwen 的理解效果，也没有读取真实 QQ。

运行 `python scripts/run_tests.py` 可执行 62 项测试。运行 `python scripts/smoke_test.py` 可执行上面的 12 项检查；它只处理临时虚构数据，结束后关闭测试进程并清理临时目录。

## 真实 QQ 测试

原设备曾实际读到指定群的 QQ 界面内容和系统通知，也曾用本地 Qwen 从通知中提取任务。

一次手机对照测试中，三个测试群应采集 3 条消息，最小化期间保存了 2 条。回到电脑后，对同一批消息逐群补采，3 条均可读取。这表明那次补采找到了遗漏，不能保证每次都能找全。

另一次三个群分别读到 11、10、13 行内容，新增保存为 0。因为没有安排新增手机发送清单，这次只能确认读取流程正常，无法据此计算新消息采集率。

## 尚未验证或未实现

- 全天运行、锁屏或关屏期间能否持续完整采集。
- 大量群聊同时收到消息，以及断网、睡眠恢复后的表现。
- 全新 Windows、其他人的电脑和不同 QQ 版本上的兼容性。
- Windows 整机重启后的完整流程；现有测试只退出并重启了程序。
- 物理断网后的完整使用流程。
- GitHub 自动检查的线上运行结果；仓库中已有配置，尚未实际运行。
- 自动翻页读取全部历史消息；当前没有此功能。

目前不支持微信自动采集：测试时 UIA 没有提供有效可读的微信消息，微信系统通知读取也未验证，只能手动粘贴或导入。
