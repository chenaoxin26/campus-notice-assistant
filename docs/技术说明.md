# 技术说明

这份说明介绍程序如何获取消息、保存任务，以及如何连接本地模型。日常安装和使用见项目首页 README。

## 消息怎样变成任务

```text
QQ 系统通知 ─────────┐
QQ 晚间窗口补采 ────┼─ 保存原文 → 本地 Qwen 分析 → 保存任务 → 界面查看或导出 Excel
手动粘贴或导入 ─────┘
```

通知读取和聊天补采是两个独立入口。一个失败时，另一个仍可以使用。AI 只分析已保存的文字，不能找回没有采集到的消息。

## 两种读取方式

**系统通知**使用 Windows 官方的 `UserNotificationListener` 接口，读取系统当前保留的通知，再按完整群名筛选。它不操作 QQ 窗口，也不清除通知。通知来源无法确认时，需要先由使用者核对，之后才交给 AI。

通知产生时间和实际保存时间分别记录。它们不一定是 QQ 消息的原始发送时间，程序不会把这些时间混用。通知文字可能不完整，同一张通知也可能被新内容替换。

**聊天补采**使用 Windows UI Automation，简称 UIA。这是 Windows 提供的界面访问接口，程序借它读取 QQ 愿意提供的界面文字。补采时会打开指定群，可能让 QQ 显示到其他窗口前面，并把未读消息变成已读。

会话列表中的摘要只用来判断哪个群可能有新消息，不当作完整正文。程序只有读到正文并保存后才记录成功。窗口不唯一、群名无法确定或电脑锁屏导致界面不可访问时，会报错并停止该次读取。

目前没有自动翻页加载全部历史消息的功能。

## 本地模型如何调用

Ollama 提供本机调用地址，Qwen 负责提取任务。程序用 `/api/tags` 查看已有模型，用 `/api/chat` 提交通知，要求模型按规定的 JSON 格式返回任务。

程序会检查返回内容是否有原文依据。时间地点不明确时保留“待确认”；“明天”等相对时间不按采集当天擅自换算。改期通知会提醒核对，不直接覆盖旧任务。

默认只连接已经运行的 Ollama。以下设置属于可选功能，需要退出助手后编辑 `data/settings.json`，再重新启动。

|配置项|作用|
|---|---|
|`api_url`|本机 Ollama 地址；只允许 HTTP 本机地址，如 `127.0.0.1` 或 `localhost`|
|`model`|已经下载的模型完整名称|
|`allow_start_model_service`|默认 `false`；主动设为 `true` 后，助手才可以尝试启动指定的 Ollama|
|`ollama_exe`|允许自动启动时，填写已有 Ollama 程序路径|
|`models_dir`|允许自动启动时，填写已有模型目录|
|`collector_root`|QQ 采集代码的位置，默认 `collector`，通常不必改|
|`groups`|允许读取的 QQ 群完整名称，也可以在界面中修改|
|`notification_poll_seconds`|通知检查间隔，默认 3 秒|
|`qq_app_ids`|额外认可的 QQ 应用标识，默认空列表；来源不确定时先人工核对|

即使允许启动模型，程序也不会下载新模型或停止其他程序的共享模型服务。

## 数据与去重

任务和通知保存在本机 SQLite 数据库中。程序保留原文、来源以及人工修改记录，已完成和已删除状态也会保存。未完成任务不会按日期自动隐藏。

聊天记录和 Windows 通知没有可以可靠对应的 QQ 原生消息编号。程序会提示相似任务供人工核对，不会因为正文相同就认定它们是同一条消息，也不会自动删除不同人发的同文通知。

`migrate.py` 保留两版任务库合并的代码，默认不会运行。它按修改时间处理同一任务的差异，保留完成或删除状态，并另存冲突记录。需要迁移时应先退出程序并备份，使用新的目标数据库。

## 文件位置

|位置|内容|
|---|---|
|`data/settings.json`|运行设置，第一次打开时从示例配置生成|
|`data/campus.sqlite3`|任务和通知原文|
|`data/collector/messages.sqlite3`|本工具保存的 QQ 界面读取记录，不是 QQ 自己的数据库|
|`data/collector/evidence`|界面读取过程记录，可能含聊天文字|
|`导出`|导出的 Excel 文件|

使用 `--data-dir` 指定其他数据目录时，聊天采集数据也跟随放在该目录下。采集子程序通过 `CAMPUS_COLLECTOR_DATA_DIR` 接收这个位置。

## 安装失败时检查什么

`setup.cmd` 会在项目目录创建 `.venv`，用 pip 安装 `requirements.txt` 中的依赖，再运行 `build.cmd`。Excel 导出使用公开的 `openpyxl` 库，不依赖 Excel、Node 或 Codex。

`build.cmd` 使用 Windows 的 .NET Framework 编译器和 WinMetadata 接口文件，从 C# 源码生成以下程序。

- `NotificationBridge.exe`：读取系统通知。
- `collector/Probe.exe`：访问 QQ 界面。
- `collector/PowerWatch.exe`：记录测试时观察到的屏幕状态。

缺少系统组件时会报错，不会自动修改系统。可先保留终端中的错误信息，检查对应文件是否存在。无需管理员权限。

没有网络时，可在可信电脑准备依赖 wheel 文件，再执行 `pip install --no-index --find-links <wheel目录> -r requirements.txt` 安装。

默认地址是 `http://127.0.0.1:8769/`。端口被占用时，可运行：

```bat
.venv\Scripts\python.exe app.py --port 8779
```

程序只允许本机访问，并检查请求来源和操作令牌，没有远程账户功能。不要直接当作公网或多人服务使用。

## Excel 导出

工作簿有“校园待办”和“消息来源”两张表。已删除任务不导出，其他任务保留当前完成状态。原始发送时间无法确认时显示“待确认”。

以 `=` 等字符开头的通知也按普通文字保存，避免被 Excel 当成公式。超过单元格长度限制的文字会标记截断，完整原文仍在数据库里。

目前不支持微信自动采集：测试时 UIA 未提供有效可读的微信消息内容，微信系统通知读取尚未验证，只能手动导入。
