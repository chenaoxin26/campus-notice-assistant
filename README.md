# AI 校园通知整理助手

白天上课时，宿舍电脑帮你记录指定 QQ 群的消息；晚上回来，点击“晚间补采并整理”，把能读到的通知整理成待办。任务保存在电脑上，之后可以修改、勾选完成，也可以导出 Excel。

程序在 Windows 11 上运行，使用电脑里已有的 Ollama 和千问 Qwen 模型分析文字。**它可能漏采消息，目前也不能自动翻页读完全部聊天历史。重要事项仍需要核对原通知。**

## 能做什么

|功能|使用方式|需要留意|
|---|---|---|
|白天记录消息|点击“开始监听”，保存指定群的 QQ 系统通知|只保存 Windows 实际收到且尚未清除的通知；通知可能缺字、合并或被替换|
|晚上补充消息|点击“晚间补采并整理”，依次打开指定群，读取近期可访问的消息|会切换 QQ 窗口，可能把群聊变成已读；不能保证读全当天消息|
|整理待办|用本地 Qwen 提取任务、截止时间和地点等信息|没有写清的内容标记“待确认”，需要人工核对|
|管理任务|查看原文，修改任务，勾选完成或删除|没完成的旧任务一直保留，不会第二天自动消失|
|手动补充|粘贴 QQ 或微信通知，也可导入 UTF-8 TXT 文件|适合自动读取失败或需要补充原文的情况|
|导出 Excel|点击“导出 Excel”|Excel 是导出时的副本，修改表格不会改动程序里的任务|

程序不会替你发送消息，也不会修改或删除 QQ、微信里的聊天记录。聊天内容和任务都保存在本机，分析时只连接本机模型服务。

## 安装和打开

需要 Windows 11、Python 3.11 或更新版本，以及已经登录的 QQ。建议使用 64 位 Python 3.12。程序曾在 Python 3.12 和 3.14.9 下测试，尚未逐个验证其他版本。

1. 在项目文件夹里运行 `setup.cmd`，等待安装和编译完成。首次安装 Python 依赖需要联网，不会下载模型。
2. 运行 `启动助手.cmd`，浏览器会打开 `http://127.0.0.1:8769/`。
3. 第一次打开没有任务，也没有选定的群聊。进入“采集设置”，添加允许读取的 QQ 群完整名称。

安装脚本只在项目目录建立 Python 运行环境，并使用 Windows 自带的 .NET Framework 编译器生成采集程序。不会改注册表或系统安全设置，也不会要求管理员权限。缺少编译器或 Windows 接口文件时会报错，排查方法见 [技术说明](docs/技术说明.md)。

程序用网页显示界面，但服务只在自己的电脑上运行，不需要安装 Excel、Node.js 或 Codex。

## 连接本地千问

Ollama 负责运行模型，Qwen 负责分析通知。先确认电脑已有 Ollama 服务和下载好的模型，再修改本程序的配置，不必重复下载。

第一次启动后会生成 `data/settings.json`。退出助手，打开这个文件，主要检查两个项目，然后重新启动助手。

|配置项|填写什么|
|---|---|
|`api_url`|Ollama 的本机地址，默认是 `http://127.0.0.1:11434`；使用其他端口时要改成实际地址|
|`model`|电脑上已有模型的完整名称，可用 `ollama list` 查看|

开发时实际使用过 `qwen3:4b-instruct-2507-q4_K_M`，约 4B 参数，采用 Q4_K_M 量化。其他模型是否合适，需要另外测试。

默认由使用者自己启动 Ollama。助手不会自动下载模型，也不会改用云端服务。模型暂时无法连接时，原文会留下等待重试；已保存的任务仍能查看、修改和导出。

## 每天怎么用

1. **白天**：保持电脑开机、联网且 QQ 已登录，在助手中点击“开始监听”。它只记录名单内的群，不会切换 QQ 窗口。
2. **晚上**：从托盘打开 QQ 普通主窗口，让需要读取的群出现在会话列表里。点击“晚间补采并整理”，确认窗口切换提示，等待处理结束。期间请暂时不要操作 QQ。
3. **检查待办**：对照消息原文检查时间地点，处理“待确认”和“可能重复”的项目。完成后勾选即可。
4. **漏掉的通知**：从“粘贴 / 导入通知”手动补充。多个通知之间用单独一行 `---` 分开，可参考 `examples/虚构通知.txt`。

修改群名单前先停止监听和实验轮读。名单支持最多 30 个群，但还没有验证 30 个群能否长期完整采集。把名单清空后，不能再启动采集。

关闭浏览器网页不会关闭后台程序。停止使用时，请在“采集设置”中点击退出按钮。

## 数据保存在哪里

- `data` 文件夹保存任务、原文和设置。退出程序后，备份整个文件夹即可。
- `导出` 文件夹保存 Excel 表格。
- 删除任务只会影响助手自己的数据，不会删除 QQ 或微信原消息。

同一条记录重复读取时会去重。不同人发的相同文字会保留；通知和聊天窗口读到的相似任务可能需要人工判断是否重复。

## 目前的限制

- QQ 系统通知可能不出现，也可能被合并、替换或清除。没有读到通知不代表群里没有消息。
- 晚间补采只读取 QQ 已经提供给程序的近期内容，没有自动向上翻页功能。聊天太多时仍可能遗漏。
- QQ 更新、同名会话或窗口隐藏到托盘，都可能使群聊定位失败。每个群的读取结果和错误会单独显示。
- 全天运行、锁屏、关屏，以及大量群聊同时收到消息等情况，还没有充分验证。
- AI 可能理解错通知。没有明确时间时不会自行补日期，改期通知会提醒核对，完成状态不会因为重复分析被重置。

一次真实测试中，最小化期间应记录 3 条消息，实际保存 2 条；返回电脑后，对同一批消息逐群补采，3 条都读到了。这个结果只适用于那次测试，不能保证每次都能补齐。

## 测试和开发记录

运行 `运行测试.cmd` 可检查程序逻辑。测试使用虚构消息，不读取真实 QQ。现有 62 项自动化测试和另外 12 项本机运行检查已通过；详细结果见 [测试记录](docs/发布验证记录.md)。

想检查自己的电脑有没有漏采，可按 [QQ 实际测试流程](docs/QQ实际测试流程.md) 从手机发送编号消息，再逐条核对。

项目发起者在了解相关技术后提出宿舍使用场景，负责需求取舍、手机实测和缺陷反馈，并提出系统通知入口与两版合并。Codex 负责代码实现和测试。过程见 [开发与协作记录](docs/开发与协作记录.md)，程序结构见 [技术说明](docs/技术说明.md)。
